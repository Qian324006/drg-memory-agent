# 标注规范（先读这个，再动 `label_tool`）

目标：给一批用户话语打上「该不该存进长期记忆」的标签，用来校准权重。

**权重只能和你给的标签一样好。** 如果你的判定标准自己都不稳定，那 80 条标出来的权重，只是把 80 个不一致的判断拟合成一个数字。

---

## 一、判定顺序（必须按这个顺序问，不要跳）

对每一句话，依次判断，**任何一步答「是」就直接判「不存」，不再往下看**：

| 顺序 | 问题 | 判「不存」的例子 |
| --- | --- | --- |
| 1 | 里面有敏感信息吗？（身份证/手机/银行卡/密码/验证码/住址/证件号） | 「我的支付密码是 865432」 |
| 2 | 这是关于**用户本人**的吗？<br>（例外：明确表达「以后怎么回答我」的风格要求，即使没说「我」也算本人） | 「我朋友说他也不吃辣」「网上有人说 DRG 会降薪」 |
| 3 | 这是一次性的吗？（问完就完、只对这一刻有意义、纯寒暄客套） | 「现在几点了」「你好呀」「再解释一遍」 |
| 4 | **半年后**，这条记忆还能让回答变得更好吗？ | 「我手机快没电了」「我有点困」 |

四步都过 → **存**。

## 二、一条防摇摆原则：拿不准就判「不存」

理由不是「保守」，是**代价不对称**：

- 误存一条垃圾记忆 → 它会被长期检索出来、拼进 system prompt、占用 token，还会把后续所有回答带偏；
- 漏存一条好记忆 → 只损失这一次的「个性化」，用户下句话还能再说一遍。

所以不确定时的默认动作是「不存」。**这条规则的作用是让 80 条标签彼此一致**，而不是让结果更好看。

## 三、字段怎么填（只在按 `e` 改字段时才需要）

| 字段 | 取值 | 判据 |
| --- | --- | --- |
| `type` | `semantic` | 关于用户或世界的事实（城市、专业、年龄） |
| | `procedural` | 怎么做 / 怎么回答我（格式、语气、流程偏好） |
| | `episodic` | 经历过或计划要做的事（比赛、面试、旅行） |
| `durability` | `permanent` | 基本不会变：性别、姓名、专业、老家的省 |
| | `long_term` | 会变但长期有效：城市、技术栈、目标、口味 |
| | `temporary` | 有明确期限或短期状态：这个月出差、最近感冒 |
| | `one_off` | 一次性：打招呼、现在就问的一个问题 |
| `explicitness` | `explicit` | 用户自己说的 |
| | `inferred` | 你从话里推出来的（「我做后端」→ 推断「懂编程」） |
| `user_specific` | `true/false` | 是否关于用户本人 |
| `action_relevance` | `high` | 影响**每次**回答：语气、格式、身份 |
| | `medium` | 偶尔相关：城市、专业、当前目标 |
| | `low` | 几乎不影响回答：编辑器偏好、口头禅 |

## 四、五个典型例子（含争议例）

| 话语 | 判定 | 理由 |
| --- | --- | --- |
| 「我在长沙读大三」 | **存** | 关于本人、长期有效、影响后续（实习、地域相关问题） |
| 「我下个月要去北京出差」 | **存** | 有期限但有价值，`temporary` + `medium`，会自然过期 |
| 「帮我记住，我明天要交作业」 | **不存** | 一次性任务。虽然用户说「记住」，但它是待办不是事实，且明天就废 |
| 「以后回答先给结论」 | **存** | 没说「我」，但这是对**本用户**的长期交互要求，`user_specific=true` |
| 「我朋友说他也不吃辣」 | **不存** | 不是关于本人。要存也是存「用户的朋友」，超出当前用户记忆的边界 |

## 五、一致性自检（必须做，30 分钟）

标完 80 条后，**隔一天**回来，随机抽 20 条重新标一次（不看你之前的答案）：

```powershell
python -m eval.label_tool --sample 20 --blind
```

- 一致率 **≥ 85%**：标签可用。
- 一致率 **< 85%**：不是你的错，是规范里还有模糊地带。回去把争议最大的那几条写进上面「争议例」，再重标。

这一步的意义：面试官如果问「你的标注可靠吗」，你能答「我做了同人重标，一致率 X%」——这是数据标注的标准做法，绝大多数候选人都答不出来。

## 六、标多少、怎么配比

| 类别 | 目标条数 | 为什么需要 |
| --- | --- | --- |
| 该存 | 40–45 | 正样本，支撑召回率 |
| 不该存 | 35–40 | 负样本，支撑精确率。现在 14:8 太偏正，精确率不稳 |
| **其中边界样本** | **≥ 25** | 临时状态、可疑偏好、非本人事实、敏感信息变形。**这些才是让权重有意义的东西** |

`eval/candidates.jsonl` 已经按 10 个分层写好 96 条候选，覆盖了上面所有类别，你直接标就行。
标完 80 条大约 **50–70 分钟**（工具会自动跳过已标的）。
